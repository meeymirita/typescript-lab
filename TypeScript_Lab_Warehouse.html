1. Зачем типы: что TypeScript ловит, а что нет #

Функция на JavaScript: списать товар со склада.

function withdraw(stock, itemId, location, qty) {
  const key = itemId + '@' + location
  if (stock[key] < qty) return { ok: false, error: 'not enough' }
  stock[key] -= qty
  return { ok: true, left: stock[key] }
}

withdraw(stock, 'bolt-m6', 'A1', '5')        // строка '5': сравнение сработает, вычитание даст NaN — молча
withdraw(stock, 'bolt-m6', 'A1')             // qty undefined → NaN
const r = withdraw(stock, 'bolt-m6', 'A1', 5)
console.log(r.left.toFixed(2))               // если ok: false — r.left undefined → TypeError в рантайме
withdraw(stock, 'bolt-m6', 5, 'A1')          // аргументы перепутаны — ключ '5@A1', ошибка не появится никогда

Четыре вызова, четыре бага, ноль ошибок в момент написания. Та же функция с типами:

type Stock = Record<string, number>
type WithdrawResult = { ok: true; left: number } | { ok: false; error: string }

function withdraw(stock: Stock, itemId: string, location: string, qty: number): WithdrawResult { /* тот же код */ }

withdraw(stock, 'bolt-m6', 'A1', '5')        // ✖ Argument of type 'string' is not assignable to parameter of type 'number'
withdraw(stock, 'bolt-m6', 'A1')             // ✖ Expected 4 arguments, but got 3
const r = withdraw(stock, 'bolt-m6', 'A1', 5)
r.left.toFixed(2)                            // ✖ Property 'left' does not exist on type '{ ok: false; error: string }'
if (r.ok) r.left.toFixed(2)                  // ✔ внутри if TS знает, что r — успешная ветка
withdraw(stock, 'bolt-m6', 5, 'A1')          // ✖ 'number' is not assignable to 'string'  — ловится… а перепутанные строки? см. сессию 2, branded types
Что TypeScript ловитЧего не ловит
неправильный тип аргумента, лишние/недостающие аргументылогические ошибки: < вместо <=
обращение к полю, которого может не быть (r.left при ok: false)данные из JSON/сети/файла: там тип — то, что вы пообещали, а не что пришло (раздел 5)
опечатки в именах полей и методовперепутанные аргументы одного типа (itemId и location — обе строки) — если не помочь (branded types)
необработанный null/undefined (в strict-режиме)всё, что происходит после as any
неполный switch по вариантам (exhaustiveness)ошибки во время выполнения вообще: типы стираются при компиляции

Что такое TypeScript на самом деле. Это JavaScript плюс описание того, какие значения где допустимы. Компилятор tsc проверяет описания и выбрасывает их: в рантайме работает обычный JS, никаких проверок типов там нет. Отсюда две вещи, которые важно принять сразу: (1) типы — это документация, которую проверяет машина; (2) на границе с внешним миром (JSON, argv, файл, HTTP) типы надо проверять кодом, а не объявлять.

ГЛАВНАЯ МЫСЛЬ ЛАБЫ

Хороший TypeScript — не «расставить : string везде». Это сделать невозможные состояния невыразимыми: результат либо успех с данными, либо ошибка с причиной — и никогда «и то и другое»; перемещение товара имеет from и to, а приход — только to; ID товара нельзя случайно передать вместо ID склада. Когда тип точно описывает область допустимого, компилятор находит баги за вас, а IDE — пишет половину кода. Каждое задание — про то, как сузить тип до ровно того, что допустимо.

2. Азбука TypeScript #

Шестнадцать вещей, без которых не прочитать ни одного файла. Каждая — определение и несколько строк на примере склада. В сессии 1 всё это пишется руками.

2.1 Аннотации и вывод типов

: тип после имени. Но чаще тип выводится из значения — аннотируйте параметры функций и публичные контракты, а локальные переменные оставляйте выводу.

let qty = 5                         // number — выведено; qty = 'x' → ошибка
const sku = 'bolt-m6'               // тип — литерал 'bolt-m6' (const не переприсвоить), а не string
let name: string                    // аннотация без значения — использовать до присваивания нельзя
function total(prices: number[]): number { return prices.reduce((a, b) => a + b, 0) }   // параметры — всегда; возврат — по желанию

2.2 Примитивы, массивы, кортежи

const a: string = 'A1', n: number = 3, b: boolean = true, big: bigint = 10n
const units: string[] = ['pcs', 'kg']          // массив строк; units.push(5) → ошибка
const pair: [string, number] = ['bolt', 3]     // кортеж: фиксированная длина и типы по позициям
const [id, count] = pair                       // id: string, count: number
const nothing: null = null, undef: undefined = undefined

2.3 Объекты, optional, readonly

type Item = {
  id: string
  name: string
  minStock?: number          // необязательное: number | undefined
  readonly sku: string       // нельзя переприсвоить после создания
}
const bolt: Item = { id: '1', name: 'Болт M6', sku: 'bolt-m6' }
bolt.sku = 'x'               // ✖ Cannot assign to 'sku' because it is a read-only property
bolt.minStock.toFixed()      // ✖ 'minStock' is possibly 'undefined'  →  bolt.minStock?.toFixed()
const x: Item = { id: '1', name: 'n', sku: 's', color: 'red' }   // ✖ Object literal may only specify known properties

2.4 Union и литеральные типы

A | B — значение одного из типов. Литерал — конкретное значение как тип: 'in' | 'out'. Это замена enum'ам в 90 % случаев и основа размеченных объединений (раздел 3).

type Unit = 'pcs' | 'kg' | 'l'
let u: Unit = 'kg'
u = 'box'                                   // ✖ Type '"box"' is not assignable to type 'Unit'
type Qty = number | 'unknown'
function show(q: Qty) { return typeof q === 'number' ? q.toFixed(1) : '—' }   // сужение через typeof

2.5 type vs interface

Оба описывают форму объекта. interface — только объекты, умеет extends и слияние деклараций (раздел 5). type — любой тип: union, кортеж, примитив, mapped. Правило лабы: type по умолчанию, interface — для контрактов, которые реализуют классы (implements) или расширяют библиотеки.

interface Entity { readonly id: string }
interface Item extends Entity { name: string }              // расширение
type Movement = MoveIn | MoveOut                             // union — только type
type ItemWithStock = Item & { stock: number }                // пересечение — «и то, и другое»

2.8 null и undefined в strict-режиме

С strictNullChecks (включён в strict) null и undefined — отдельные типы, и TS не даст обратиться к полю значения, которое может быть пустым. Инструменты: ?., ??, сужение if, и в крайнем случае ! (обещание «точно не пусто» — на вашей совести).

const item = items.find(i => i.sku === sku)        // Item | undefined
item.name                                          // ✖ 'item' is possibly 'undefined'
item?.name ?? 'не найден'                          // ✔
if (!item) throw new Error('not found'); item.name // ✔ после проверки — Item
item!.name                                         // ✔ компилируется; в рантайме упадёт, если undefined

2.9 enum vs as const

enum Unit { Pcs = 'pcs', Kg = 'kg' }                  // генерирует объект в рантайме; синтаксис не из JS
const UNITS = ['pcs', 'kg', 'l'] as const              // readonly-кортеж литералов: обычный JS
type Unit = (typeof UNITS)[number]                     // 'pcs' | 'kg' | 'l' — тип выведен из значения
UNITS.includes(x as Unit)                              // список для валидации в рантайме — бесплатно

В лабе — as const + вывод типа: одно значение даёт и рантайм-список, и тип. enum оставляем для чужого кода (в Nest он встречается).

2.10 Приведение: as и satisfies

const el = document.querySelector('#qty') as HTMLInputElement   // «я знаю лучше»: TS верит; ошибка проявится в рантайме
interface Config { units: string[]; maxQty: number }
const cfg = { units: ['pcs', 'kg'], maxQty: 1000 } satisfies Config   // проверить соответствие, НЕ меняя выведенный тип
cfg.units[0]                                                     // 'pcs' | 'kg' — литералы сохранились (с `: Config` было бы string)

2.11 Generics — тип как параметр

Функция, работающая с любым типом, но сохраняющая его: first(items: Item[]): Item, first(nums: number[]): number — одна функция first<T>(items: T[]): T. T подставляется при вызове, обычно выводится. Подробно — раздел 4.

function first<T>(items: T[]): T | undefined { return items[0] }
const i = first(items)          // Item | undefined — T выведен как Item
const n = first([1, 2, 3])      // number | undefined
function byId<T extends { id: string }>(list: T[], id: string): T | undefined   // ограничение: T должен иметь id

2.12 keyof, typeof, индексный доступ

type ItemKey = keyof Item              // 'id' | 'name' | 'minStock' | 'sku'
type ConfigFromValue = typeof cfg      // тип из значения (typeof в позиции типа — не рантайм-typeof)
type SkuType = Item['sku']             // тип поля

2.13 Классы

Как в ООП-лабе на PHP, но с выводом типов: модификаторы public/private/protected, readonly, параметры-свойства в конструкторе, abstract, implements. private в TS — проверка компилятора (стирается); #field — настоящая приватность JS. Раздел 6.

import/export как в ES-модулях. import type { Item } — импорт только типа (стирается; с verbatimModuleSyntax обязателен для типов). Расширение .js в путях при module: NodeNext — да, даже для .ts-файлов: так требует Node ESM.

3. Структурная типизация и сужение #

3.1 Структурная типизация — «утиная» с проверкой

В TS тип — это форма. Если у значения есть все нужные поля нужных типов, оно подходит, как бы ни назывался его тип. Имя типа не важно; важна структура.

interface Entity { id: string }
const item = { id: '1', name: 'Болт' }
const e: Entity = item                 // ✔ лишнее поле name не мешает: у item есть всё, что нужно Entity
const e2: Entity = { id: '1', name: 'Болт' }   // ✖ а вот литерал прямо в аннотацию — «лишние свойства» (excess property check)

type ItemId = string; type LocationId = string
function move(item: ItemId, loc: LocationId) {}
move(locationId, itemId)               // ✔ компилируется: оба — string. Структурно одинаковы. Решение — branded types, сессия 2

3.2 Сужение (narrowing) — TS следит за if

Внутри условия TS «знает», что проверка прошла, и сужает тип переменной. Способы:

ПриёмПримерСужает

3.3 Размеченное объединение (discriminated union) — сердце лабы

type Movement =
  | { kind: 'in';       itemId: string; to: string;   qty: number; unitCost: number }
  | { kind: 'out';      itemId: string; from: string; qty: number; reason: 'sale' | 'writeoff' }
  | { kind: 'transfer'; itemId: string; from: string; to: string; qty: number }

function describe(m: Movement): string {
  switch (m.kind) {                         // kind — дискриминант: литерал, уникальный в каждом варианте
    case 'in':       return `+${m.qty} → ${m.to} по ${m.unitCost}`     // здесь m — только вариант 'in': есть unitCost, нет from
    case 'out':      return `−${m.qty} из ${m.from} (${m.reason})`
    case 'transfer': return `${m.qty}: ${m.from} → ${m.to}`
    default:         return assertNever(m)  // m здесь — never: все варианты разобраны. Добавите 4-й вариант — ошибка компиляции ЗДЕСЬ
  }
}
function assertNever(x: never): never { throw new Error(`unexpected: ${JSON.stringify(x)}`) }

Сравните с одним типом { kind: string; from?: string; to?: string; unitCost?: number; reason?: string }: у прихода может быть from, у расхода — unitCost, и каждое использование — if (m.from) с молитвой. Размеченное объединение делает неправильные комбинации невыразимыми, а assertNever превращает «забыли обработать новый вариант» в ошибку компиляции.

🔬 Под капотом: type predicate и assertion function — как научить TS своей проверке
function isMovement(x: unknown): x is Movement {          // возвращает boolean, но TS запоминает: true ⇒ x: Movement
  return typeof x === 'object' && x !== null && 'kind' in x && ['in', 'out', 'transfer'].includes((x as { kind: unknown }).kind as string)
}
function assertMovement(x: unknown): asserts x is Movement {   // после вызова x сужен во всём остальном коде
  if (!isMovement(x)) throw new TypeError('not a movement')
}
const raw: unknown = JSON.parse(line)
if (isMovement(raw)) describe(raw)        // ✔
assertMovement(raw); describe(raw)        // ✔

Опасность: predicate — это ваше обещание. Если внутри проверка неполная (проверили kind, не проверили qty), TS всё равно поверит. Поэтому на настоящих границах — Zod (раздел 5), который строит проверку из схемы и не даст соврать.

4. Generics и типы-утилиты #

4.1 Generics — параметризация типом

// функция
function groupBy<T, K extends keyof T>(list: T[], key: K): Map<T[K], T[]> { … }
groupBy(movements, 'kind')            // Map<'in' | 'out' | 'transfer' | 'adjust', Movement[]> — K выведен как 'kind', T[K] — тип поля

// тип
type Result<T, E> = { ok: true; value: T } | { ok: false; error: E }
type Paginated<T> = { items: T[]; total: number; page: number }

// класс / интерфейс
interface Repository<T extends { id: string }> { get(id: string): T | undefined; save(e: T): void }
class InMemoryRepository<T extends { id: string }> implements Repository<T> { … }
const items = new InMemoryRepository<Item>()

// ограничения и значения по умолчанию
function pluck<T, K extends keyof T>(obj: T, key: K): T[K]
type ApiResponse<T = unknown> = { data: T; status: number }

Правило: generic нужен, когда тип на входе должен сохраниться на выходе. Если T встречается один раз — это unknown, а не generic.

4.3 Mapped, conditional, template literal — как утилиты устроены

// mapped: пройти по ключам и построить новый тип
type Partial<T>  = { [K in keyof T]?: T[K] }
type Totals<T>   = { [K in keyof T]: number }                   // те же ключи, все значения number
type Getters<T>  = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] }   // переименование ключей

// conditional: если-то на уровне типов; распределяется по union
type Unwrap<T> = T extends Promise<infer U> ? U : T             // infer — «вытащи то, что там внутри»
type Extract<U, M> = U extends M ? U : never                    // для каждого варианта union отдельно

// template literal: строки как типы
type Group = 'item' | 'stock'
type Action = 'add' | 'list'
type Command = `${Group}:${Action}`                             // 'item:add' | 'item:list' | 'stock:add' | 'stock:list'
type EventName = `${Lowercase<Group>}.${string}`               // 'item.что-угодно'

Эти три механизма — весь «продвинутый TS». Их не надо изобретать каждый день; их надо узнавать в ошибках компилятора и в сигнатурах библиотек (Vue, Pinia, Zod, Express — всё на них).

🔬 Под капотом: распределительные условные типы и ловушка с never

type Ex<U, M> = U extends M ? U : never при U = 'a' | 'b' | 'c' применяется к каждому члену отдельно и результаты объединяются — поэтому Extract работает. Чтобы не распределять, оборачивают в кортеж: [U] extends [M] ? …. И never в позиции U даёт never (пустой union → пустой результат) — источник загадочных «почему тип стал never». В сессии 3 это встретится в типе клиента API.

abstract class Repository<T extends Entity> {                      // abstract — как в PHP

  #secret = 1                                                      // настоящее приватное поле JS (не стирается)
}

// packages/core/src/domain/movement.ts
import type { ItemId, LocationId, MovementId } from './ids.js'

interface MovementBase {
  readonly id: MovementId
  readonly at: string                 // ISO-дата
  readonly itemId: ItemId
  readonly qty: number
  readonly note?: string
}

export type MovementIn       = MovementBase & { readonly kind: 'in';       readonly to: LocationId; readonly unitCost: number }
export type MovementOut      = MovementBase & { readonly kind: 'out';      readonly from: LocationId; readonly reason: OutReason }
export type MovementTransfer = MovementBase & { readonly kind: 'transfer'; readonly from: LocationId; readonly to: LocationId }
export type MovementAdjust   = MovementBase & { readonly kind: 'adjust';   readonly location: LocationId; readonly reason: string }   // qty может быть отрицательным

export type Movement = MovementIn | MovementOut | MovementTransfer | MovementAdjust

export const OUT_REASONS = ['sale', 'writeoff', 'sample'] as const
export type OutReason = (typeof OUT_REASONS)[number]

export type MovementKind = Movement['kind']                                   // 'in' | 'out' | 'transfer' | 'adjust'
export type MovementOf<K extends MovementKind> = Extract<Movement, { kind: K }>   // MovementOf<'in'> = MovementIn

export function describe(m: Movement): string {
  switch (m.kind) {
    case 'in':       return `+${m.qty} ${m.itemId} → ${m.to} (по ${m.unitCost})`
    case 'out':      return `−${m.qty} ${m.itemId} из ${m.from} (${m.reason})`
    case 'transfer': return `${m.qty} ${m.itemId}: ${m.from} → ${m.to}`
    case 'adjust':   return `${m.qty > 0 ? '+' : ''}${m.qty} ${m.itemId} в ${m.location}: ${m.reason}`
    default:         return assertNever(m)
  }
}

export function assertNever(x: never): never {
  throw new Error(`Необработанный вариант: ${JSON.stringify(x)}`)
}

/** Куда движение прибавляет и откуда убавляет — «нормализация» четырёх вариантов в общий вид. */
export function deltas(m: Movement): ReadonlyArray<{ location: LocationId; delta: number }> {
  switch (m.kind) {
    case 'in':       return [{ location: m.to, delta: m.qty }]
    case 'out':      return [{ location: m.from, delta: -m.qty }]
    case 'transfer': return [{ location: m.from, delta: -m.qty }, { location: m.to, delta: m.qty }]
    case 'adjust':   return [{ location: m.location, delta: m.qty }]
    default:         return assertNever(m)
  }
}

// packages/core/src/domain/stock.ts
import type { ItemId, LocationId } from './ids.js'
import { deltas, type Movement } from './movement.js'
import { err, ok, type Result } from '../lib/result.js'

/** Ключ остатка: товар@склад. Тип-шаблон: строка определённой формы. */
export type StockKey = `${string}@${string}`
export const stockKey = (item: ItemId, location: LocationId): StockKey => `${item}@${location}`

export type Stock = Readonly<Record<StockKey, number>>              // иммутабельный снимок: apply возвращает новый

export type StockError =
  | { code: 'NON_POSITIVE_QTY';  qty: number }
  | { code: 'SAME_LOCATION';     location: LocationId }
  | { code: 'INSUFFICIENT';      itemId: ItemId; location: LocationId; have: number; need: number }

export function applyMovement(stock: Stock, m: Movement): Result<Stock, StockError> {
  if (m.kind !== 'adjust' && m.qty <= 0)                      return err({ code: 'NON_POSITIVE_QTY', qty: m.qty })
  if (m.kind === 'transfer' && m.from === m.to)               return err({ code: 'SAME_LOCATION', location: m.from })

  const next: Record<StockKey, number> = { ...stock }          // копия; здесь мутируем только её
  for (const { location, delta } of deltas(m)) {
    const key  = stockKey(m.itemId, location)
    const have = next[key] ?? 0                                 // noUncheckedIndexedAccess: number | undefined → number
    const after = have + delta
    if (after < 0) return err({ code: 'INSUFFICIENT', itemId: m.itemId, location, have, need: -delta })
    next[key] = after
  }
  return ok(next)
}

export function quantity(stock: Stock, item: ItemId, location: LocationId): number {
  return stock[stockKey(item, location)] ?? 0
}

/** Человекочитаемое описание ошибки — exhaustive по code. */
export function explain(e: StockError): string {
  switch (e.code) {
    case 'NON_POSITIVE_QTY': return `количество должно быть больше нуля, получено ${e.qty}`
    case 'SAME_LOCATION':    return `перемещение внутри одного склада ${e.location} бессмысленно`
    case 'INSUFFICIENT':     return `на складе ${e.location} только ${e.have} ${e.itemId}, нужно ${e.need}`
  }
}

const isRecord = (x: unknown): x is Record<string, unknown> => typeof x === 'object' && x !== null
const isString = (x: unknown): x is string => typeof x === 'string'
const isNumber = (x: unknown): x is number => typeof x === 'number' && Number.isFinite(x)
const isOutReason = (x: unknown): x is OutReason => isString(x) && (OUT_REASONS as readonly string[]).includes(x)

/** Ручной парсер: unknown → Movement | null. Каждое поле — своя проверка. */
export function parseMovement(x: unknown): Movement | null {
  if (!isRecord(x) || !isString(x.id) || !isString(x.at) || !isString(x.itemId) || !isNumber(x.qty)) return null
  const base = { id: movementId(x.id), at: x.at, itemId: itemId(x.itemId), qty: x.qty, ...(isString(x.note) ? { note: x.note } : {}) }
  switch (x.kind) {
    case 'in':       return isString(x.to) && isNumber(x.unitCost) ? { ...base, kind: 'in', to: locationId(x.to), unitCost: x.unitCost } : null
    case 'out':      return isString(x.from) && isOutReason(x.reason) ? { ...base, kind: 'out', from: locationId(x.from), reason: x.reason } : null
    case 'transfer': return isString(x.from) && isString(x.to) ? { ...base, kind: 'transfer', from: locationId(x.from), to: locationId(x.to) } : null
    case 'adjust':   return isString(x.location) && isString(x.reason) ? { ...base, kind: 'adjust', location: locationId(x.location), reason: x.reason } : null
    default:         return null
  }
}

export function assertMovement(x: unknown): asserts x is Movement {
  if (parseMovement(x) === null) throw new TypeError(`Не похоже на движение: ${JSON.stringify(x)}`)

// packages/core/src/lib/repository.ts
export interface Entity { readonly id: string }

/** Хранилище сущностей с id. T — что храним; T['id'] — тип ключа (для branded id — он же). */
export interface Repository<T extends Entity> {
  get(id: T['id']): T | undefined
  save(entity: T): void
  remove(id: T['id']): boolean
  list(where?: Partial<T>): readonly T[]
}

export class InMemoryRepository<T extends Entity> implements Repository<T> {
  protected readonly items = new Map<T['id'], T>()

  constructor(seed: readonly T[] = []) { for (const e of seed) this.items.set(e.id, e) }

  get(id: T['id']): T | undefined { return this.items.get(id) }
  save(entity: T): void { this.items.set(entity.id, entity); this.persist() }
  remove(id: T['id']): boolean { const had = this.items.delete(id); if (had) this.persist(); return had }

  list(where: Partial<T> = {}): readonly T[] {
    const keys = Object.keys(where) as (keyof T)[]                 // Object.keys → string[]; сужаем сами (см. 1.5)
    return [...this.items.values()].filter(e => keys.every(k => e[k] === where[k]))
  }

  protected persist(): void {}                                      // хук для наследников
}
// packages/core/src/lib/json-repository.ts
import { existsSync, readFileSync, writeFileSync } from 'node:fs'
import { InMemoryRepository, type Entity } from './repository.js'

/** Файл — граница: содержимое unknown, каждую запись подтверждает guard. */
export class JsonFileRepository<T extends Entity> extends InMemoryRepository<T> {
  constructor(private readonly path: string, private readonly guard: (x: unknown) => x is T) {
    super(JsonFileRepository.load(path, guard))                     // seed родителю — из файла
  }

  private static load<T>(path: string, guard: (x: unknown) => x is T): T[] {
    if (!existsSync(path)) return []
    const raw: unknown = JSON.parse(readFileSync(path, 'utf8'))
    if (!Array.isArray(raw)) throw new TypeError(`${path}: ожидался массив`)
    return raw.filter(guard)                                        // filter с type predicate сужает элементы до T
  }

  protected override persist(): void {                              // override — ошибка, если в родителе метода нет
    writeFileSync(this.path, JSON.stringify([...this.items.values()], null, 2))
  }
}

// packages/core/src/lib/typed-emitter.ts

/** Карта событий: имя → кортеж аргументов. Задаётся потребителем. */
export type EventMap = Record<string, readonly unknown[]>
type Listener<Args extends readonly unknown[]> = (...args: Args) => void

export class TypedEmitter<Events extends EventMap> {
  private readonly listeners: { [K in keyof Events]?: Listener<Events[K]>[] } = {}   // mapped type: те же ключи, значения — массивы слушателей

  on<K extends keyof Events>(event: K, listener: Listener<Events[K]>): () => void {
    ;(this.listeners[event] ??= []).push(listener)
    return () => this.off(event, listener)                                          // отписка — как в Vue-лабе
  }

  off<K extends keyof Events>(event: K, listener: Listener<Events[K]>): void {
    this.listeners[event] = this.listeners[event]?.filter(l => l !== listener)
  }

  emit<K extends keyof Events>(event: K, ...args: Events[K]): void {                // ...args типизирован кортежем события
    this.listeners[event]?.forEach(l => l(...args))
  }
}

  movements: Repository<Movement>
  events?: TypedEmitter<WarehouseEvents>

export class Warehouse {
  private stock: Stock = {}
  readonly events: TypedEmitter<WarehouseEvents>
  private readonly now: () => Date
  private readonly nextId: () => string

  constructor(private readonly deps: WarehouseDeps) {
    this.events = deps.events ?? new TypedEmitter()
    this.now    = deps.now ?? (() => new Date())
    this.nextId = deps.nextId ?? randomUUID
    for (const m of deps.movements.list()) {                      // восстановить остатки из журнала
      const r = applyMovement(this.stock, m)
      if (r.ok) this.stock = r.value
    }
  }

  addItem(input: NewItem): Item {
    const item: Item = { id: itemId(input.sku.toLowerCase()), ...input }
    this.deps.items.save(item)
    return item
  }

  /** Принимает движение без id/at — их выдаёт сервис. Distributive Omit: применяется к каждому варианту union. */
  apply(input: DistributiveOmit<Movement, 'id' | 'at'>): Result<Stock, StockError | { code: 'UNKNOWN_ITEM'; itemId: ItemId }> {
    const item = this.deps.items.get(input.itemId)
    if (!item) return { ok: false, error: { code: 'UNKNOWN_ITEM', itemId: input.itemId } }

    const movement = { ...input, id: movementId(this.nextId()), at: this.now().toISOString() } as Movement
    const r = applyMovement(this.stock, movement)
    if (!r.ok) return r

    this.stock = r.value
    this.deps.movements.save(movement)
    this.events.emit('movement.applied', movement, this.stock)
    this.checkLow(item, movement)
    return ok(this.stock)
  }

  quantity(item: ItemId, location: LocationId): number { return quantity(this.stock, item, location) }
  snapshot(): Stock { return this.stock }

  private checkLow(item: Item, m: Movement): void {
    if (item.minStock === undefined) return
    const locations = m.kind === 'in' ? [m.to] : m.kind === 'out' ? [m.from] : m.kind === 'transfer' ? [m.from, m.to] : [m.location]
    for (const loc of locations) {
      const q = this.quantity(item.id, loc)
      if (q < item.minStock) this.events.emit('stock.low', item, loc, q)
    }
  }
}

// packages/core/src/api/client.ts — один generic-запрос на все маршруты
import type { ApiContract, Route } from '../api-contract.js'

type Opts<R extends Route> = Omit<ApiContract[R], 'response'>                     // { query?: … } | { body: … } | {}
/** Если все опции необязательны ({} подходит) — аргумент необязателен; иначе (есть body) — обязателен. */
type Args<R extends Route> = {} extends Opts<R> ? [opts?: Opts<R>] : [opts: Opts<R>]

export function createClient(baseUrl: string, fetchImpl: typeof fetch = fetch) {
  return async function request<R extends Route>(route: R, ...args: Args<R>): Promise<ApiContract[R]['response']> {
    const [method, path] = route.split(' ') as [string, string]                    // 'GET /stock' → ['GET', '/stock']; форма ключа гарантирована типом
    const opts = ((args as [Opts<R>?])[0] ?? {}) as { query?: Record<string, string | undefined>; body?: unknown }   // внутри generic-функции Args<R> не разрешён — читаем как «возможно один элемент»
    const qs = opts.query
      ? '?' + new URLSearchParams(Object.entries(opts.query).filter((e): e is [string, string] => e[1] !== undefined))
      : ''
    const res = await fetchImpl(`${baseUrl}${path}${qs}`, {
      method,
      headers: { 'content-type': 'application/json' },
      body: opts.body === undefined ? undefined : JSON.stringify(opts.body),
    })
    if (!res.ok && res.status !== 422) throw new Error(`${route} → HTTP ${res.status}`)   // 422 — бизнес-отказ в теле (Result), не исключение
    return (await res.json()) as ApiContract[R]['response']
  }
}

Такое расхождение «форма UI ≠ доменный тип» нормально; важно, что переход между ними — в одном месте (computed) и проверяется компилятором.

11. Глоссарий #

Аннотация типа — x: T — явное указание типа; альтернатива — вывод из значения.
Вывод типов (inference) — компилятор определяет тип по значению, возврату, контексту (колбэки).
Стирание типов — типы существуют только при компиляции; в JS их нет — отсюда необходимость проверок на границах.
Структурная типизация — совместимость по форме, а не по имени типа.
Excess property check — литерал объекта прямо в аннотации не может содержать лишних полей; переменная — может.
Union / пересечение — A | B — одно из; A & B — всё вместе.
Литеральный тип — конкретное значение как тип: 'in', 42, true.
as const — сделать литерал readonly с сохранением литеральных типов; источник для типов через typeof.
Размеченное объединение — union объектов с общим полем-дискриминантом (kind, code, ok); сужается через switch/if.
Сужение (narrowing) — уточнение типа переменной внутри условия: typeof, instanceof, in, равенство, predicates.
Type predicate — функция (x): x is T; true ⇒ TS считает x типом T.
Assertion function — функция (x): asserts x is T; после вызова x сужен, иначе — исключение.
Exhaustiveness — проверка полноты разбора вариантов через never (assertNever) или satisfies Record<Union, …>.
unknown — что угодно, но использовать нельзя без сужения. Тип всего внешнего.
any — отключение проверки. Не использовать.
never — тип без значений: «сюда не попадём», результат исчерпания union.
Branded type — примитив с фантомной меткой в типе — номинальность; создаётся только конструктором.
Result — union «успех с value | ошибка с error»; отказ виден в сигнатуре.
Generic — параметр типа: функция/класс/тип, работающие с любым T, сохраняя его.
Ограничение (extends) — T extends Entity — T обязан иметь форму; внутри доступны её поля.
keyof / typeof / T[K] — ключи типа / тип значения / тип поля (indexed access).
Mapped type — { [K in keyof T]: … } — новый тип по ключам существующего; основа Partial, Readonly, Record.
Conditional type — A extends B ? X : Y; распределяется по union, если A — голый параметр; infer вытаскивает часть.
Template literal type — строковый тип заданной формы: `${G}:${A}`.
satisfies — проверить соответствие типу, сохранив точный выведенный тип значения.
as — утверждение типа: компилятор верит; ответственность на вас.
Утилитные типы — Partial, Required, Readonly, Pick, Omit, Record, Extract, Exclude, ReturnType, Parameters, NonNullable, Awaited.
readonly — запрет присваивания поля / мутирующих методов массива на уровне типа.
Declaration merging — интерфейсы с одним именем сливаются; способ расширить чужие типы.
.d.ts / declare — файл только с типами; declare — «существует где-то, описываю форму».
Zod — библиотека схем: рантайм-валидация + z.infer — тип из схемы.
strict — набор строгих флагов; без него TS — подсказки, а не проверка.
tsx / esbuild / tsc — запуск без проверки / сборка без проверки / проверка (и сборка) с типами.
Workspaces — несколько пакетов в одном репозитории с общими зависимостями; @warehouse/core импортируется по имени.
